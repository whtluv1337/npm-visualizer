# Визуализатор зависимостей npm

Практическая работа №2, вариант 23.

Реализованы все пять этапов:
1. Конфигурация через TOML.
2. Получение зависимостей npm-пакетов.
3. Рекурсивный BFS, фильтрация и обработка циклов.
4. Определение порядка зависимостей.
5. Визуализация в D2, SVG и ASCII.

## Требования

Python 3.11+ (встроенная библиотека `tomllib`). Сторонние Python-пакеты
не требуются.

## Структура

- `src/` — исходный код;
- `tests/` — автоматические тесты;
- `configs/` — примеры настроек TOML;
- `fixtures/` — учебные графы;
- `run.bat`, `run.sh` — скрипты запуска.

## Запуск

Windows PowerShell:

```powershell
.\run.bat configs\test.toml
```

Linux/macOS: `./run.sh configs/test.toml`.

Тесты: `python -m unittest discover -s tests -v`.

## Настройки

В TOML указываются шесть обязательных полей:

- `package` — имя пакета для анализа;
- `repository` — URL npm registry или путь к учебному JSON;
- `test_mode` — `true` для учебного JSON;
- `output` — путь к будущему SVG;
- `ascii_tree` — показывать ли ASCII-дерево;
- `filter_substring` — исключать пакеты, содержащие эту подстроку.

На первом этапе приложение выводит все настройки и проверяет ошибки.

## Этап 2 — прямые зависимости npm

```powershell
.\run.bat configs\npm.toml
```

Программа обращается к публичному HTTP API реестра npm (`/package/latest`),
из поля `dependencies` получает **прямые runtime-зависимости** и выводит их.
Не используется npm CLI или библиотека для анализа зависимостей.
`devDependencies`, `peerDependencies` и `optionalDependencies` не включаются.
Необходим доступ в интернет. Для текущего этапа анализируется релиз
`latest` каждого npm-пакета.

## Этап 3 — рекурсивный BFS

Граф строится по уровням. Вложенная функция `visit_level` рекурсивно
переходит к следующему уровню; множество `visited` защищает от циклов.
Фильтр `filter_substring` исключает совпадающие имена и их ветви.

Учебный режим использует JSON вида `{"A": ["B"], "B": []}`. Все вершины
обязаны присутствовать в словаре, имена — только заглавные латинские буквы.

```powershell
.\run.bat configs\test.toml
.\run.bat configs\cycle.toml
.\run.bat configs\filter.toml
```

## Этап 4 — порядок зависимостей

Алгоритм Кана строит топологический порядок: зависимости размещаются перед
пакетом, который от них зависит. Если граф содержит цикл, корректного
полного порядка нет: программа честно показывает заблокированные вершины.

```powershell
.\run.bat configs\test.toml
.\run.bat configs\cycle.toml
```

### Сопоставление с настоящим npm

`npm` не задаёт публично фиксированный последовательный порядок установки:
он разрешает версии, использует кеш, может выполнять загрузки параллельно.
Полученный нами порядок — **логический порядок зависимостей**, а не
точное время выполнения операций npm.

Для сопоставления на компьютере с Node.js:

```powershell
npm view is-number dependencies --json
npm install is-number --package-lock-only --ignore-scripts
npm ls is-number --all
```

Наш инструмент по умолчанию получает `latest` для каждого пакета. npm
разрешает диапазоны версий (`^`, `~`), peer/optional-зависимости и может
переиспользовать/поднимать пакеты в дереве. Поэтому состав и порядок
вложенных зависимостей могут отличаться. Кроме того, `npm ls` показывает
дерево связей, **не хронологический порядок загрузки**.

## Этап 5 — D2, SVG, ASCII

Программа сохраняет рядом `output/*.d2` и `output/*.svg`. Если установлен
официальный CLI `d2`, SVG создаётся с помощью него. В противном случае
используется встроенный простой SVG-рендерер, строящий те же вершины и рёбра.
SVG можно открыть в браузере. Флаг `ascii_tree` включает дерево в консоли.

Три разных учебных пакета A, B, C:

```powershell
.\scripts\demo_three.bat
```

Или отдельно:

```powershell
.\run.bat configs\package_a.toml
.\run.bat configs\package_b.toml
.\run.bat configs\package_c.toml
```

Результаты: `output/package_a.svg`, `output/package_b.svg`,
`output/package_c.svg` (файлы результата не коммитятся).

## Этапы и Git

В Git-истории пять последовательных коммитов типа `feat(scope): ...`.
Каждый коммит соответствует отдельному этапу. Для просмотра:

```powershell
git log --oneline --reverse
```

Список ограничений и способ сравнения с настоящим npm описаны отдельно
в `examples/comparison.md`. Это учебный анализ структуры зависимостей,
не замена алгоритма разрешения версий npm.

Для **реального автоматического сравнения** списка прямых зависимостей с
`npm view` (при наличии Node.js/npm и интернета):

```powershell
python -m scripts.compare_npm configs\npm.toml
```

В этом скрипте npm вызывается **только для сравнения** на этапе 5, а не
для получения графа в основном приложении. Порядок загрузки следует
сопоставлять с оговорками из `examples/comparison.md`.
