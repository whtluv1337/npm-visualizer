# Сравнение с npm: что сравнивать при защите

## Проверка фактических данных

1. Запустить `run.bat configs\npm.toml` при доступном интернете.
2. Выполнить `npm view is-number dependencies --json`.
3. Сравнить прямые зависимости: обе команды смотрят данные npm registry,
   но `npm view` может по умолчанию выбирать текущий dist-tag `latest`.
4. Для дерева пакетов выполнить в отдельной временной директории
   `npm install is-number --package-lock-only --ignore-scripts`, затем
   открыть `package-lock.json` и изучить версии вложенных пакетов.

## Почему возможны расхождения

- Здесь для КАЖДОЙ вершины берётся `/latest`, а npm разрешает версии
  согласно диапазонам (`^`, `~`, точная версия), а не только `latest`.
- Здесь учитываются `dependencies`, но не `peerDependencies`,
  `optionalDependencies` и `devDependencies`.
- npm может удалять дубликаты, поднимать зависимости и ставить их
  параллельно, поэтому порядок строк в `npm ls` не является порядком
  загрузки. Наш алгоритм даёт допустимый **топологический порядок**.
- При циклах строгого полного топологического порядка не существует.

В окружении без npm/доступа к реестру сравнение результатов реальных
запусков не проведено; это воспроизводимая методика, а не придуманные
наблюдения.
